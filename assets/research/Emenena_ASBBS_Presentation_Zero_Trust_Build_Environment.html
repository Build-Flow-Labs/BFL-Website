Zero-trust visibility into your build environment

Zero Trust for CI/CD

Applying NIST 800-207 principles to build pipelines:

  • Never trust implicitly - Every tool, secret, and configuration must be verified
  • Continuous verification - Not just at deployment, but every build
  • Least privilege - Minimal secret scope, restricted token permissions
  • Assume breach - Design for detection, not just prevention

The Four-Axis Health Model

1. Tool Currency

Are Actions pinned to SHA digests or floating on mutable tags?

2. Secret Hygiene

Minimal scope? Leaking to logs? Token permissions?

3. Build Provenance

Can artifacts trace back to commit, runner, workflow?

4. Vulnerability Posture

Dependabot alerts addressed? Dependencies current?
